# 足迹标签

## 能做什么

- **编辑页**：「标签」输入框，逗号分隔；下面按已有记录列出「常用标签」气泡，点一下补进输入框。
- **列表页**：搜索框下面一排筛选胶囊（`全部 N`、`海边 1`…），点一下只看带该标签的记录；卡片上直接显示标签。
- **相册页**：到达日期下方显示这条记录的标签。
- **搜索**：除了地点、见闻，也会匹配标签。

## 数据怎么存

标签是**记录自己的一个字段**，没有另开表——一条足迹的标签是一小组短文本，
筛选在客户端做（本地记录本来就全量读出排序），所以 `text[]` 足够。

```sql
alter table public.trip_footprints
  add column if not exists tags text[] not null default '{}';   -- docs/supabase/trip-footprints-tags.sql
```

| 层 | 位置 |
| --- | --- |
| 服务端 | `trip_footprints.tags text[] not null default '{}'` |
| 本地记录 | `tags: string[]`（`footprintsRepository.normalizeFootprint` 统一归一化） |
| 同步 | `manualSync` 的 `toRemoteFootprint` / `toLocalFootprint` / `select(...)` 三处都带 `tags` |

归一化兼容三种历史形态：数组、逗号分隔字符串、字段缺失（同步下来的旧记录），
所以**不需要给老数据写迁移脚本**。

## 解析规则（`footprintTags.ts`）

- 分隔符：中英文逗号 `,，`、顿号 `、`、分号 `;；`、空白、`#`（从别处粘过来的习惯写法）。
- 去重大小写不敏感（保留第一次出现的写法），一条记录最多保留 12 个标签。
- 和 UI 拆开的纯函数：`parseTagInput` / `normalizeTags` / `formatTagsInput` / `collectTagCounts` / `itemHasTag`，
  便于单测，也便于以后在别处复用。

## 配色（`tagColors.ts`）

做法与「简笔（Notes）」里的标签一致：**按标签文本算一个稳定的颜色**，同一个标签在任何页面都是同一个颜色，
不会每次渲染乱跳；底色是同色的低透明度版本（`主色 + 24`，约 14%），所以一张卡片上多个标签也不会互相打架。

- 常见标签给了更贴切的指定色：海边/海岛（青）、日落（橙）、周末（绿）、朋友/假期（紫）、美食（珊瑚）、咖啡（浅棕）、夜景/出差（靛）…
- 其余走哈希落到色板；色板是挑过的，去掉了原色板里偏灰、偏暗的几支（例如棕色），保证在白卡片上干净。
- 哈希写法与 Notes 里的 `tagHash` 相同，因此同名标签在两个 App 里颜色一致。

## 卡片布局

标签加进来后卡片一度变成「一行行堆高」，因此顺手压成两行信息 + 图片：

| | 之前 | 现在 |
| --- | --- | --- |
| 标题 | 地点独占一行 | `地点 · 城市` 一行 |
| 城市 | 单独一行 | 同上，次要文字跟在后面 |
| 日期 / 标签 / 同步状态 | 各自一行 | 合成一行 |

标签最多直接显示 3 个，多出来的折成 `+N`；`Tag` 组件新增 `compact` 模式（11px、更小内边距）供卡片使用，
相册等其它地方保持原样。地点/城市都限制一行并允许收缩，长地名会省略号截断而不是把城市挤下去。

## 验证

- 单测：`__tests__/footprintTags.test.ts`（12 条，分隔符/去重/上限/统计/匹配）+ `__tests__/tagColors.test.ts`（5 条，稳定性/大小写/底色/指定色）。
- `npx tsc --noEmit` 0 错误；`npx jest` 全绿。
- 模拟器实测：编辑页输入标签 → 保存 → 列表出现筛选胶囊与卡片标签 → 点胶囊筛选 → 相册显示标签 → 编辑页回显并把其它记录用过的标签显示为「常用标签」。

## 已知限制

- 服务端 imgproxy 无法处理 HEIC：`/storage/v1/render/image/...` 返回 `422 Invalid source image`，
  所以列表/相册里 HEIC 照片的缩略图会加载失败（原图直链正常，JPEG/PNG 不受影响）。
  要修需要客户端本地生成缩略图、或上传时额外存一张 JPEG、或给 imgproxy 加 HEIC 支持。
